# 工作流

1. 阅读 AGENTS 指定文件；核查工作目录、身份、origin、SSH、HEAD/分支及用户改动。
2. 追加 DEV_PROGRESS 和层进度计划：目标、文件、测试、备份范围、回滚。
3. 在安全已提交基线上建唯一 backup/pre-phase<N>-<scope>-<yyyymmdd-hhmm> 并 push，核验远端哈希；在 main 开发。
4. 按当前 Phase 逐部分实施和报备；小改动、小验证，不导入未经审核的旧模块。
5. 执行 lint/工具测试及阶段测试。失败保留首次错误、原因、修复和复测；停止扩展直到可解释。
6. 核对实现/合同/需求/进度是否一致；未知/模拟/未验证都显式标明。
7. 追加 LOG、HANDOFF、层记录、MEMORY；审查 diff/status/敏感和大文件，显式 git add 文件。
8. 提交 A 并 push，ls-remote 核验；必要时记录 A 至审计 B，再推送核验 B。B 不记录自身哈希。
9. 报告真实成果、未完成、测试、A/B/备份和工作区。清理自己启动的长跑进程，不终止用户进程。

网络/沙箱阻塞按受控权限流程处理，不关闭 SSH 主机验证，不读私钥，不全局装依赖。无用户授权不得自动采购、上传采集素材、下载受限权重或改变模型路线。
